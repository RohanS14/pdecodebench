For each physically-valid no-comment code sample (mod_type = NoComm_Valid), we generate a corrupted-comment variant (mod_type = CorrComm) by injecting comments from a donor example drawn from a different PDE class and numerical method. The positions of the injected comments are determined by the ground-truth commented version of the same code (mod_type = Comm_Valid), ensuring comments appear at locations that are natural for that specific codebase. The texts at those positions are replaced with donor comment texts in order, preserving donor comment order. 
If the donor has fewer comments than receiver slots, donor comments are cycled in order to fill all slots, ensuring the corrupted version always has exactly the same number of comments as its Comm_Valid counterpart. If the donor has more comments than receiver slots, only the first n_receiver donor comments are used and the remainder are discarded. The resulting code has the correct structure and variable names of the original solver, but comments that describe a completely different physical system. Provenance is recorded in corruption_source_id, corruption_source_pde, and injected_comments. delta_comments records n_donor - n_receiver prior to cycling or truncation, capturing whether the donor had more or fewer comments than the receiver required.
